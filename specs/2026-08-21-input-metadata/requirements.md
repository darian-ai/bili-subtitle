## 背景与目标

阶段一已经建立可运行、可测试的 CLI 骨架。阶段二需要把用户提供的视频标识稳定地解析为一个普通 UGC 投稿，并取得按平台顺序排列的分集及 CID，为后续登录和字幕提取提供不依赖平台响应结构的领域输入。

完成后，用户应能通过现有主命令输入 BV 号、av 号、常见官方视频 URL 或 `b23.tv` 短链，并看到所选投稿和分集的稳定纯文本摘要。阶段二只验证输入、获取元数据和执行分集选择，不登录、不发现或下载字幕，也不创建输出文件。

## 范围

- 解析裸 BV 号、裸 av 号、官方完整视频 URL 和 `b23.tv` 短链。
- 从完整 URL 读取可选的 `p` 查询参数，并保存为分集选择提示。
- 通过 Bilibili 元数据适配器取得投稿标题、aid、bvid、分集序号、CID 和分集标题。
- 将平台响应转换为与 HTTPX、Typer 和接口字段解耦的领域模型。
- 实现 URL `p`、`--page` 和 `--all-pages` 的选择优先级、互斥和越界检查。
- 将解析、元数据获取和分集选择接入现有主命令。
- 使用稳定纯文本输出投稿标识和所选分集摘要。
- 使用脱敏固定响应覆盖正常结果和平台异常，默认测试不得访问真实网络。

## 输入契约

### 裸标识

- 解析前忽略输入整体的首尾空白，不从任意说明文字中搜索或截取标识。
- av 标识由 `av` 或 `AV` 前缀及正整数 aid 组成；规范化结果使用小写 `av`。
- BV 固定前缀允许大小写差异，规范化结果使用大写 `BV`；主体字符保持原值并按 Bilibili BV 标识格式校验，不得整体转为大写或小写。
- 零、负数、缺少主体、包含空白或非法字符的标识作为无效输入处理。

### 完整 URL

- 只接受 `http` 或 `https`，主机为 `bilibili.com`、`www.bilibili.com` 或 `m.bilibili.com`，路径为 `/video/<BV或av标识>`，可带尾随 `/`、查询参数或片段。
- URL 中的视频标识遵循裸标识的规范化和校验规则。
- 拒绝用户信息、显式端口、非视频路径、路径中的额外业务段、非官方主机以及仅以相似后缀伪装的主机。
- 与分集选择无关的查询参数和片段不参与领域结果。
- `p` 若出现必须恰好有一个正整数值；空值、零、负数、非整数或重复的 `p` 均为无效输入，即使显式选项随后会覆盖它也不忽略格式错误。

### b23.tv 短链

- 接受 `http` 或 `https` 的 `b23.tv` 和 `www.b23.tv` URL，拒绝用户信息和显式端口。
- 由 Bilibili 适配器执行有限次数的 HTTP 重定向，不使用浏览器自动化。
- 每个重定向目标必须仍属于 `b23.tv` 或上述受支持的 Bilibili 主机；最终目标必须是受支持的完整视频 URL。
- 重定向缺失、形成循环、超过上限、跳往非官方域名或落到范围外页面时，返回短链重定向错误。
- 短链 URL 自身和最终视频 URL 中若都存在 `p`，以最终视频 URL 的 `p` 为准；短链服务中间跳转参数不进入领域模型或日志。

## 分集选择规则

1. `--page N` 与 `--all-pages` 互斥；同时使用时在任何网络请求前返回用法错误。
2. `--page N` 选择第 N 个分集，并覆盖 URL 的 `p`；存在 URL `p` 时输出简短覆盖提示。
3. `--all-pages` 选择全部分集，并覆盖 URL 的 `p`；存在 URL `p` 时输出简短覆盖提示。
4. 没有显式选项但 URL 含 `p=N` 时，只选择第 N 个分集。
5. 没有显式选项且 URL 不含 `p` 时，默认选择全部分集。
6. `N` 必须为正整数且对应元数据中的真实 P 序号；超出范围或缺失对应序号时返回无效分集错误。
7. 全部分集严格保留平台元数据中的顺序，不按 CID、标题或其他字段重新排序，也不扩展到其他 BV 投稿。

## 领域模型与边界

- `VideoReference` 表达规范化后的 bvid 或 aid，以及 URL 提供的可选页码；同一引用只持有一种输入标识。
- `VideoPage` 表达正整数 P 序号、正整数 CID 和分集标题。
- `VideoMetadata` 表达正整数 aid、规范 bvid、投稿标题和不可变的有序 `VideoPage` 集合。
- `PageSelection` 表达投稿元数据、不可变的所选分集集合和选择来源，不复制或修改分集内容。
- 领域层使用标准库 `dataclasses`、`enum` 和显式解析函数，不导入 Typer、Rich、HTTPX 或具体 Bilibili 接口代码。
- 平台接口字段只存在于基础设施适配层；缺失、类型错误、非法值或重复 P 序号不得以半有效模型进入应用层。
- 阶段二的领域对象不得持有 Cookie、请求头、重定向历史或任何临时 URL。

## 元数据适配器

- 阶段二加入 HTTPX 运行时依赖，并使用同步 Client、统一请求头、连接与读取超时及重定向控制。
- 视频元数据通过集中管理的 Bilibili Web 元数据接口按 bvid 或 aid 查询，不在 CLI 或领域层拼装接口请求。
- 适配器必须检查 HTTP 状态、平台结果码、顶层对象及分集列表结构，再创建领域模型。
- 不存在或已删除、当前访问无权限、网络失败和响应结构异常必须映射为稳定的领域错误，不把平台原始消息作为产品契约直接透传。
- 阶段二不读取 Credential Manager、不发送已保存 Cookie，也不为权限或风控拒绝增加绕过或替代接口。
- 不实现缓存、并发请求或无限重试；短链解析完成后只请求其最终投稿的元数据。

## CLI 输出与失败

- 成功输出使用固定字段的纯文本，不使用依赖终端宽度的 Rich 表格，也不新增 JSON 输出选项。
- 摘要包含投稿标题、规范 bvid、aid、选择数量，以及每个所选分集的 P 序号、CID 和标题；分集逐行按平台顺序输出。
- 平台标题中的控制字符必须在终端展示边界安全处理，不能借此生成额外伪造日志行；领域值本身保持平台返回内容。
- 显式选项覆盖 URL `p` 时，在摘要前输出不含 URL 的简短提示。
- 无效输入、投稿不存在或删除、无权限、无效分集、网络失败、短链重定向失败和平台响应结构异常使用可区分的简体中文提示。
- 任一阶段二失败均属于没有产生有效提取结果的整体失败，CLI 返回退出码 `2`，不得创建 `subtitles/` 或其他业务输出。

## 已确定决策

1. 支持常见官方视频 URL，而不是任意 Bilibili 子域或从文本中模糊提取标识。
2. 输入采用适度容错：裁剪整体空白并兼容标识前缀大小写，但严格校验主体和 URL 边界。
3. 显式分集选项覆盖 URL `p` 时执行 Mission 规定的优先级并明确提示，不把共存视为错误。
4. 阶段二替换主命令的提取占位行为，真实获取元数据并输出摘要；认证子命令继续保持阶段一占位行为。
5. 摘要为人类可读的稳定纯文本；阶段二不增加 `--json` 或其他公开选项。
6. 错误按产品含义分类，平台错误码只用于适配器判断和测试，不直接成为 CLI 契约。
7. 固定响应可以来自公开接口的脱敏样本；不得包含 Cookie、账号信息、签名 URL 或不必要的个人数据。

## 不在范围内

- 二维码登录、凭据检查、保存、复用或清除。
- 字幕轨道发现、字幕正文下载及 JSON、SRT、manifest 写入。
- `--lang` 过滤和 `--force` 文件覆盖行为；选项继续存在，但阶段二不据此执行字幕或文件操作。
- 番剧、影视、课程、互动视频、收藏夹、合集、UP 主空间或多个投稿输入。
- WBI、APP 私有接口、媒体下载、ASR、OCR、翻译或访问控制绕过。
- 对 CLI 纯文本摘要作长期机器可读格式承诺。

## 安全与兼容约束

- 所有网络请求必须具有明确超时，短链重定向必须限制次数和目标域名。
- 输入和平台标题均视为不可信数据；错误信息不得回显完整重定向链或内部响应正文。
- 测试默认不联网、不读取真实凭据，且只使用明显的伪数据和脱敏响应。
- 技术标识保留英文，说明、状态、提示和决策使用简体中文。
- Windows 是优先运行环境；URL、模型和选择纯逻辑不得无理由依赖 Windows 专有 API。
