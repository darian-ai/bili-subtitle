## 一、使命

`bili-subtitle` 是一款 Windows 优先、面向个人用户的 Python 命令行工具。它提取 Bilibili 播放器已经提供、且当前账号正常可见的字幕轨道，包括人工字幕和 AI 字幕，并将字幕保存为原始 JSON 与 SRT。

本项目解决的是“取回站内已有字幕”，不是“从视频中识别字幕”。

## 二、核心用户流程

1. 用户输入一个 BV 号、av 号、完整 Bilibili 视频 URL 或 `b23.tv` 短链。
2. 工具解析投稿、分集和 CID。
3. 如果没有有效登录状态，工具显示二维码；登录成功后自动继续原任务。
4. 工具发现所选分集的全部可见字幕轨道。
5. 工具立即下载字幕 JSON，原样保存，并从同一数据生成 SRT。
6. 工具输出处理摘要，清楚区分成功、跳过、无字幕和失败。

## 三、V1 产品契约

### 输入与命令

主命令：

```text
bili-subtitle <视频标识或URL> [--page N | --all-pages] [--lang 语言代码] [--force]
```

认证命令：

```text
bili-subtitle auth login
bili-subtitle auth status
bili-subtitle auth clear
```

分集规则：

- URL 含 `?p=N` 时，默认只处理第 N 个分集。
- 未指定分集时，默认处理该投稿的全部分集。
- `--page N` 和 `--all-pages` 优先于 URL 的 `p` 参数，且两者互斥。
- 一次命令只处理一个 UGC 投稿，不自动扩展到其他 BV 投稿。

字幕规则：

- 默认提取所选分集的全部可见字幕轨道。
- `--lang` 可以重复使用，用于按平台语言代码过滤轨道。
- 人工字幕和 AI 字幕一视同仁；AI 字幕是平台已有轨道，不由本工具生成。
- 字幕文字、标点、空格、时间范围和分段必须保持原样。

### 登录与权限

- 首次运行或凭据失效时自动显示二维码。
- 登录成功后自动恢复原提取任务，不要求重新执行命令。
- 凭据必须存入 Windows Credential Manager，不得保存在工作区明文文件中。
- 二维码过期、取消或失败必须有明确终止结果，不得无限轮询。
- 工具只访问当前账号通过正常网页流程可见的字幕，不实现权限或风控绕过。

### 输出

默认输出位置：

```text
当前工作目录/
└── subtitles/
    └── 视频标题 [BV号]/
        ├── P01-分集标题.语言.轨道ID.json
        ├── P01-分集标题.语言.轨道ID.srt
        └── manifest.json
```

- 原始 JSON 保存字幕正文接口返回的内容。
- SRT 使用 UTF-8 编码，并从同一份 JSON 生成。
- 所有分集都保留 `P` 序号，以获得稳定文件名。
- `manifest.json` 记录视频、分集、CID、语言、轨道属性、输出文件和处理结果。
- 已有文件默认逐个跳过；`--force` 才允许覆盖。
- 某轨道只缺少 JSON 或 SRT 时，只补齐缺少的文件。
- 必须安全处理 Windows 非法字符、保留名称、尾随字符和过长文件名。

### 失败与退出码

- 单个分集或轨道失败时继续处理其他项目，并保留成功结果。
- 无字幕、字幕不可访问、登录失效、网络失败和接口异常必须使用不同提示。
- 退出码 `0`：正常完成，包括无字幕或全部跳过。
- 退出码 `1`：部分项目成功、部分项目失败。
- 退出码 `2`：请求整体失败，没有产生有效结果。
- 输出文件必须安全写入，不能把未完成文件伪装成成功结果。

## 四、不可违背的原则

### 原则一：只提取站内已有字幕

不得下载媒体后执行 ASR，不得截图后执行 OCR，也不得在站内字幕缺失时偷偷启用识别降级路径。

### 原则二：忠实保存原文

不得翻译、润色、补标点、修改空格、繁简转换、重新分段或合并双语字幕。

### 原则三：安全处理账号信息

Cookie、二维码密钥和带签名的字幕 URL 不得出现在终端日志、异常文本、manifest、测试快照或普通配置文件中。带签名字幕 URL 只允许在内存中短暂存在，并应立即使用。

### 原则四：正常访问，不做绕过

不支持付费、地区、登录、会员或平台风控绕过；接口拒绝正常访问时，应明确失败。

### 原则五：局部失败不破坏整体结果

多分集和多轨道处理必须隔离失败。已经成功生成的文件不得因后续失败而被删除。

### 原则六：规格先于实现

新增或改变产品行为时，必须先更新 `specs/`。未进入 Constitution 的功能不得直接实现。

## 五、V1 范围

### 包含

- 普通 UGC 单分集和多分集投稿。
- 当前账号可见的人工字幕和 AI 字幕。
- BV、av、完整视频 URL 和 `b23.tv` 短链输入。
- 二维码登录、凭据复用、JSON/SRT/manifest 导出。
- 全部轨道、语言过滤、已有文件处理和部分失败恢复。
- Windows 优先的安装、凭据存储与文件系统兼容。

### 不包含

- 视频、音频、封面和弹幕下载。
- ASR、OCR、翻译、润色、繁简转换和双语合并。
- 番剧、影视、课程、互动视频和访问控制绕过。
- 收藏夹、UP 主空间、跨投稿合集和批量 URL。
- GUI、浏览器扩展、独立 EXE 和自动更新服务。

## 六、成功标准

V1 只有同时满足以下条件才算完成：

- 用户通过一个主命令完成字幕提取，不需要手工复制 Cookie。
- 带 AI 字幕的视频能为每条所选轨道生成 JSON 和 SRT。
- 单分集、多分集、多语言及同语言多轨道行为正确且不会覆盖。
- SRT 内容与原始 JSON 对应，不发生文本处理。
- 无字幕与访问失败可以明确区分。
- 重复运行默认不覆盖；部分失败保留成功结果并返回正确退出码。
- 测试与实际输出中不存在凭据或临时签名 URL。
- 整个代码库不存在媒体下载、ASR、OCR 或访问控制绕过路径。

## 七、唯一真实来源规则

1. `mission.md` 负责产品使命、行为和边界。
2. `tech-stack.md` 负责技术、架构和工程约束。
3. `roadmap.md` 负责阶段顺序和阶段验收。
4. README 只提供项目入口和使用方法，不重新定义 Constitution。
5. 代码注释解释实现原因，不替代规格。
6. 规格变更必须同步检查另外两份文档是否受影响。
7. 技术标识保留原文，所有解释、状态和决策均使用简体中文。
