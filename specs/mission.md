## 一、使命

`bili-study` 是一款 Windows 优先、本地优先、面向个人用户并采用 Apache-2.0 许可证的视频学习工具。它以 Bilibili 播放器已经提供、且当前账号正常可见的字幕为可信来源，帮助用户在观看前把握学习目标和视频结构，在观看中主动思考、复述并记录带时间戳的个人笔记，在观看后生成可验证、可长期复习的学习材料。

已完成的 `bili-subtitle` 字幕提取能力继续作为稳定基础和兼容命令。V2 不重新实现另一套字幕抓取逻辑，而是在规范化字幕、证据引用和安全凭据边界之上增加学习助手、本地知识资产与浏览器交互。

本项目要解决的是“怎样借助已有字幕更有效地学习视频内容”，不是用 AI 替用户看完视频，也不是从媒体中识别字幕。

## 三、核心用户流程

### 已完成：字幕提取流程

1. 用户输入 BV 号、av 号、完整 Bilibili 视频 URL 或 `b23.tv` 短链。
2. 工具解析投稿、分集和 CID。
3. 没有有效登录状态时显示二维码，登录成功后自动继续原任务。
4. 工具发现所选分集的全部可见人工或 AI 字幕轨道。
5. 工具立即下载字幕 JSON，原样保存，并从同一数据生成 SRT。
6. 工具输出处理摘要，区分成功、跳过、无字幕、无匹配和失败。

### 计划交付：视频学习流程

1. 用户创建一个本地命名知识库，配置自备的 OpenAI-compatible 云端模型，并启动 `bili-study serve`。
2. 用户在 Chrome 或 Edge 打开普通 Bilibili 知识视频，通过配对后的侧栏主动点击“生成学习指南”。
3. 本地服务复用现有认证与字幕能力，取得当前 BV、P 和用户选择的字幕轨道，构建带稳定 cue ID、时间戳和正文哈希的 Transcript revision。
4. 模型先生成全视频学习目标、章节节奏和不直接泄露答案的引导问题；章节详细要点只在用户主动展开时生成。
5. 播放过程中侧栏只跟随并高亮当前章节，不自动暂停、弹题、上传或生成。
6. 用户可以主动记录普通笔记、疑问、重点和复述；个人笔记自动绑定当前视频时间戳。
7. 用户提交回答或复述后，AI 只能根据字幕证据指出已覆盖内容、遗漏和可能误解，并给出可点击回看的时间片段。
8. 生成材料输出为可移植 Markdown；个人笔记与可重建的 AI 内容分离，重新生成不得覆盖个人内容。

## 四、公开产品契约

### 命令与兼容性

当前已完成并继续有效的命令：

```text
bili-subtitle <视频标识或URL> [--page N | --all-pages] [--lang 语言代码]... [--force]
bili-subtitle auth login|status|clear
bili-study extract <视频标识或URL> [现有提取选项]
bili-study auth login|status|clear
```

后续阶段计划新增：

```text
bili-study library create|list|remove
bili-study config provider set|status|clear
bili-study plugin pair
bili-study serve [--port 8765]
bili-study doctor
```

- `bili-study extract` 与 `bili-subtitle` 使用同一提取实现和行为契约。
- V2 不以产品改名为理由破坏已有输入、认证、输出、退出码或安全规则。
- 首个插件原型由用户手动启动本地服务；自动安装或唤起 Native Messaging Host 不在首期范围。

### 学习指南

- 首版面向通用知识视频，不假定内容属于编程、语言或应试课程。
- 学习指南至少包含学习目标、章节标题、章节时间范围和每章引导问题。
- 长字幕必须完整分块处理，不能为了适配模型上下文直接截断后半部分。
- 首次生成先返回全局大纲；章节总结、关键点、术语和易遗漏细节按需生成。
- 引导问题应促进用户思考、回答和复述；初始界面不得同时展示标准答案。
- AI 生成的事实、反馈和回看建议必须引用当前 Transcript revision 中存在的 cue；无法验证的内容不得伪装成字幕事实。
- 资料不足时明确说明无法判断，不允许用模型常识填充为视频原意。

### 学习交互

- 所有模型请求、详细内容、回答反馈和导出均由用户主动触发。
- 插件可以高亮当前章节和显示进度，但默认不暂停播放器、不遮挡视频、不强制答题。
- 用户可以跳过问题、只做笔记或稍后复习；工具不得把单一学习方法强加为完成门槛。
- 首个主动学习闭环采用“结构化笔记 + AI 预生成问题 + 用户回答/复述 + 证据化反馈”。
- 点击任一证据或个人时间戳笔记应能返回对应 BV、P 和视频时间。

### 本地数据与 Obsidian

- 用户创建命名知识库并选择 Markdown 目录；目录可以位于 Obsidian Vault，也可以由其他 Markdown 工具管理。
- 个人笔记是不可被自动生成覆盖的用户资产；AI 指南和索引属于可重建数据。
- 机器数据库、模型缓存和任务状态默认保存在本机应用数据目录，不要求用户运行数据库服务。
- 首期只输出标准 Markdown、YAML frontmatter、双链和时间戳链接，不依赖 Obsidian 专用插件。
- V2 后续才引入显式批量入库、语义索引和跨视频检索；收藏夹、合集与 UP 主自动同步不属于首期。

### 模型与隐私

- 用户自备 OpenAI-compatible 云端 API 的基础 URL、模型和 API Key。
- API Key 必须保存在 Windows Credential Manager，不得写入扩展存储、项目文件、Markdown、数据库或命令历史。
- 用户第一次生成前必须清楚知道字幕内容将发送至其配置的模型服务。
- 插件不得直接访问模型 API、Bilibili 字幕接口或 Credential Manager；所有敏感能力只存在于配对后的本地服务。
- 终端、扩展、日志、异常、数据库、Markdown 和测试快照不得泄漏 Cookie、API Key、二维码密钥或字幕签名 URL。
- 后续云端 Embedding 功能必须另行提示：首次语义索引会把全部字幕分块发送给配置的服务。

## 五、不可违背的原则

### 原则一：AI 辅助学习，不替代学习

优先促进用户理解、回忆、回答和复述，不以“一键生成大量内容”作为唯一成功标准。AI 不得自动替用户完成个人笔记或把生成文本伪装为用户理解。

### 原则二：证据优先

Transcript revision 是 AI 学习内容的事实边界。章节、问题、反馈、导图、测验和跨视频回答都必须能够引用稳定 cue 与时间戳；推断必须与来源事实明确区分。

### 原则三：忠实保留来源

原始字幕 JSON 和 SRT 的 V1 忠实性契约继续有效。规范化、分块和 AI 处理不得反向修改原始字幕，也不得覆盖来源证据。

### 原则四：个人内容不可破坏

个人笔记、回答、复述和复习记录与可重建生成物分离。重新生成、模型切换、索引重建和软件升级都不得静默覆盖个人内容。

### 原则五：本地优先、上传显式

知识库、笔记、任务状态和缓存默认留在本机。任何字幕或个人内容发送到云端前必须由用户执行明确操作，并遵循最小必要数据原则。

### 原则六：正常访问，不做绕过

只使用当前账号通过正常网页流程可见的字幕，不支持付费、地区、会员、登录、风控或平台权限绕过。

### 原则七：兼容与局部失败

已有字幕提取能力不得因 V2 退化。视频、章节、模型任务或导出局部失败时保留已经成功的来源、生成物和个人笔记，并提供可恢复状态。

### 原则八：规格先于实现

新增或改变产品行为时先更新 Constitution、对应阶段需求和验收标准。未进入规格的能力不得直接实现或标记完成。

## 六、版本范围

### V1：字幕提取，已完成

- 普通 UGC 单分集和多分集投稿。
- BV、av、完整视频 URL 与 `b23.tv` 短链。
- 二维码登录、凭据复用、JSON/SRT/manifest 导出。
- 全部轨道、语言过滤、已有文件处理、Windows 路径安全和部分失败恢复。

### V2 首个原型：视频学习侧栏，未开始

- `bili-study` 学习命令、命名知识库、模型配置和手动本地服务。
- Chrome/Edge Manifest V3 侧栏及安全配对。
- 真实字幕到两阶段 AI 学习指南。
- 章节跟随、结构化个人笔记、引导问题、回答/复述和证据化反馈。
- 可移植 Markdown/Obsidian 输出。

### V2 后续增量，未开始

- 学习助手 MVP：取消与恢复、缓存/成本提示、章节小测、总结和基础导图。
- 复习闭环：错题、置信度、回看片段、间隔复习和 Anki 导出。
- 跨视频知识库：显式批量入库、云端 Embedding、混合检索、问答与观点比较。

### 明确不在当前范围

- 视频、音频、封面和弹幕下载。
- ASR、OCR，以及无字幕时的媒体识别降级。
- 付费、地区、会员、风控和其他访问控制绕过。
- 自动暂停、自动上传、自动生成或强制学习检查。
- 番剧、影视、课程专用页面和互动视频适配。
- 中心化账号服务、云端托管知识库、计费平台和跨设备同步。
- 首期扩展商店发布、Obsidian 专用插件、桌面 GUI 和独立 EXE。

## 七、成功标准

### V1 完成标准

V1 已满足字幕提取、真实 AI 字幕忠实性、多分集、重复跳过、`--force`、安全审计、Windows CI 和本地安装标准；其完成证据保留在 Roadmap 和阶段六 validation 中。

### V2 插件原型完成标准

只有同时满足以下条件才可标记首个 V2 原型完成：

- 用户能按文档完成模型配置、本地知识库创建、服务启动和扩展配对。
- Chrome 与 Edge 能识别当前普通视频页，并通过现有认证流程取得真实字幕。
- 长字幕不截断，学习目标、章节和引导问题来自完整 Transcript。
- 插件不自动暂停，所有模型操作均由用户主动触发。
- 用户能保存带时间戳的结构化笔记，并在刷新和服务重启后恢复。
- 用户能回答或复述，AI 反馈只引用有效字幕证据。
- 点击证据能回到对应视频片段，允许误差不超过两秒。
- 重新生成、模型错误和任务失败不覆盖个人笔记。
- 默认自动化测试无真实网络、账号或模型调用，且现有 V1 回归全部通过。
- 任何输出和本地数据中均不存在凭据或字幕签名 URL。

## 八、唯一真实来源规则

1. `mission.md` 负责产品使命、公开契约、行为原则和范围。
2. `tech-stack.md` 负责当前与计划技术、架构边界、安全和质量约束。
3. `roadmap.md` 负责 V1/V2 阶段顺序、状态和阶段验收。
4. README 只提供当前已经可用能力的安装与使用方法；未实现 V2 功能不得写成现有用法。
5. 已完成 V1 阶段文档保留为历史验收证据，不因 V2 重写。
6. 技术标识保留原文，所有解释、状态和决策使用简体中文。
