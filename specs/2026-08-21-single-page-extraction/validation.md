# 阶段四：单分集提取闭环验证及合并标准

## 自动化质量门禁

在仓库根目录依次运行：

```powershell
uv sync --locked --dev
uv run pytest
uv run ruff check .
uv run ruff format --check .
uv run pyright
```

全部命令必须返回 `0`。pytest 必须在无网络、无账号、无真实 Credential Manager 和无真实等待环境通过，分支覆盖率不低于 90%。Windows GitHub Actions 必须在待合并提交上运行同一组检查并通过。

## 轨道发现验证矩阵

| 场景 | 期望证据 |
|---|---|
| 一个 AI 字幕轨道 | 得到身份完整的 `AI` 轨道，语言、名称和 ID 正确 |
| 一个人工字幕轨道 | 得到身份完整的 `HUMAN` 轨道，不误标为工具生成 |
| 混合多轨道与同语言轨道 | 数量、平台顺序和各自轨道 ID 均保持，不去重 |
| 合法空字幕列表 | 返回明确无字幕正常结果，不请求正文 |
| 缺失字幕区但平台定义为无字幕 | 按固定结构规则判定无字幕，并由测试锁定 |
| 列表或轨道字段异常 | 返回平台响应结构异常，不降级为空列表 |
| 会话失效 | 返回需登录，不在本阶段自行扫码或循环 |
| 权限拒绝 | 返回不可访问，不尝试其他接口或绕过 |
| 连接、超时或服务端故障 | 返回网络失败，调用有界 |

所有场景使用脱敏固定响应和 HTTP 替身；默认测试必须能证明没有未拦截网络请求。

## 签名 URL 生命周期与安全

- 用全仓唯一伪签名 URL 金丝雀驱动成功、HTTP 失败和解析失败测试。
- 断言轨道发现后选定 URL 被立即请求，并使用同一个同步 HTTPX Client 的会话与超时配置。
- 断言协议相对 URL 只补全到允许的 HTTPS Bilibili 主机；非 HTTPS、非受信任主机、用户信息和异常端口均拒绝。
- 检查领域对象、应用结果、异常文本、标准输出、标准错误、日志、`repr`、manifest、文件名、pytest 快照与提交文件，均不得包含完整或查询部分金丝雀。
- 断言适配器不缓存 URL、不把 URL 暴露为公开返回值，也不在失败时透传请求或响应正文。

## 正文 JSON 校验与原样保存

| 场景 | 期望结果 |
|---|---|
| 合法 AI 字幕固定响应 | `.json` 与 HTTP 原始响应字节逐字节相等 |
| 非规范空白、键顺序、转义与额外字段 | 原样保留，不经 `json.dumps` 重写 |
| Unicode、前后空格、空正文和内部换行 | 校验通过，领域正文逐字符一致 |
| 片段时间重叠或输入非单调 | 保持响应顺序，不排序或合并 |
| 缺少列表或片段字段 | 平台响应结构异常，不创建成功目标 |
| 字段类型错误或布尔值冒充数值 | 平台响应结构异常 |
| NaN、Infinity、负时间或结束早于开始 | 平台响应结构异常 |
| 非 UTF-8、非 JSON、顶层非对象 | 平台响应结构异常，消息不含原文 |

测试必须同时证明解析用对象只负责校验和生成 SRT，落盘 JSON 始终来自同一次响应的原始字节。

## SRT 忠实性验证

- 条目编号严格按 JSON 片段顺序从 1 连续递增。
- 起止时间按十进制 `ROUND_HALF_UP` 规则转换为 `HH:MM:SS,mmm`；覆盖零、半毫秒边界和超过一小时。
- 对每个片段逐字符比较 SRT 正文与 JSON 正文字段；前后空格、标点、Unicode 和内部换行必须保留。
- 重叠、相同时间戳和非单调片段不得被排序、合并、拆分或校正。
- 除 SRT 必需编号、时间行和分隔空行外，不出现翻译、润色、补标点、繁简转换或其他文本变换。
- 输出可按 UTF-8 严格解码，并具有由测试锁定的确定性换行约定。

## 安全写入故障矩阵

| 注入故障点 | 期望结果 |
|---|---|
| JSON 临时文件创建/写入/关闭/替换失败 | 无成功 JSON，无 SRT/manifest 成功记录，临时文件被清理 |
| SRT 临时文件创建/写入/关闭/替换失败 | JSON 成功文件可保留；无伪成功 SRT/manifest，临时文件被清理 |
| manifest 创建/写入/关闭/替换失败 | 已发布 JSON/SRT 保留；整体报告导出失败，无残留临时 manifest |
| 任一目标已存在 | 明确失败且原文件字节不变，不提前实现覆盖或跳过 |
| 非法或不可写目录 | 返回导出失败，不显示文件内容或秘密 |

临时文件必须与目标位于同一目录且名称唯一。成功后目录中只能存在预期 JSON、SRT 和 manifest；失败后不得存在可被误认为成功结果的目标或遗留临时文件。

## manifest 验证

- 固定 schema 版本存在且类型稳定。
- bvid、aid、视频标题、P 序号、CID、分集标题、轨道 ID、语言、显示名称和人工/AI 属性与输入模型一致。
- JSON/SRT 只记录输出目录内的相对文件名，处理结果只有两者成功发布后才为成功。
- manifest 使用 UTF-8 且内容确定；相同输入重复生成的预期字节一致。
- manifest 不包含绝对路径、Cookie、二维码、请求头、完整播放器响应、正文响应或签名 URL。
- manifest 写入顺序在 JSON/SRT 之后，由调用记录或故障注入测试证明。

## 单分集闭环场景

1. 构造一个脱敏普通 UGC 视频、确定的 P 序号/CID 和包含 AI 字幕的播放器固定响应。
2. 发现轨道并由测试调用方按轨道 ID 明确选定一条，不依赖“第一条”或语言猜测。
3. 证明签名 URL 被立即请求一次，正文响应同时供应原始 JSON 与 SRT 转换。
4. 断言生成 `<基名>.json`、`<基名>.srt`、`manifest.json`，内容与身份全部一致。
5. 分别替换为人工字幕、无字幕、需登录、不可访问、网络失败、异常结构和导出失败，确认结果分类稳定。
6. 断言任何失败不触发媒体下载、ASR、OCR、备用私有接口或访问控制绕过。

该闭环必须通过应用服务及基础设施替身完成，而不是只分别测试孤立函数。

## 回归、架构与范围审计

- 阶段一 CLI 帮助、入口与质量工具全部回归通过。
- 阶段二 BV/av/URL/短链、元数据与分集选择全部回归通过。
- 阶段三认证命令、凭据复用、一次自动恢复和秘密保护全部回归通过。
- 公开主命令在阶段四仍保持阶段三元数据摘要，不产生不完整的“首分集/首轨道”字幕行为。
- 领域层仅导入标准库；CLI 不直接请求字幕接口、不接触签名 URL、不写字幕文件。
- 播放器接口、平台字段、受信任 URL 校验与响应映射只存在于 Bilibili 基础设施层。
- 运行时依赖没有新增字幕、媒体、浏览器自动化或识别库；代码搜索不存在 FFmpeg、媒体下载、ASR、OCR、翻译、WBI、APP 私有接口或绕过实现。
- 不存在多分集/全部轨道循环、`--lang` 过滤、已有文件跳过/补齐、`--force` 覆盖、文件名完整策略或最终退出码聚合；这些属于阶段五。

## Windows 人工检查

在 Windows 上仅使用脱敏固定数据与新建临时目录执行：

1. 运行离线单分集闭环测试，打开输出 JSON，确认其字节/显示形式保留固定响应的空白、Unicode 与额外字段。
2. 用 UTF-8 打开 SRT，抽查编号、时间、标点、前后空格和多行正文。
3. 打开 manifest，确认身份与相对文件名正确且不含伪签名 URL、Cookie 或绝对路径。
4. 执行故障注入用例后检查目录，确认没有遗留临时文件或伪成功目标。

阶段四不要求真实账号或真实投稿网络提取；真实 AI 字幕提取属于阶段六明确人工验收，避免在阶段四规格或记录中保存平台临时秘密。
