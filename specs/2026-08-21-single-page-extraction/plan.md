# 阶段四：单分集提取闭环实施计划

## 执行状态

- 任务组 1—7：已按测试先行完成并分批提交。
- 任务组 8：本地自动化、Windows 脱敏临时目录检查、安全与范围审计已完成；
  feature 分支推送后的 Windows CI 尚待执行。
- 下列任务复选框是实施基线；完成证据以 [`validation.md`](./validation.md) 的验证记录为准。

## 1. 用失败测试冻结阶段边界与领域契约

- [ ] 为人工/AI 轨道、字幕片段、单轨道结果和分类错误先建立失败测试。
- [ ] 锁定领域模型的不可变性、非空身份、非负有限时间、原始顺序和正文不变约束。
- [ ] 用架构测试证明领域层不依赖 Typer、Rich、HTTPX、keyring 或平台响应对象。
- [ ] 锁定阶段四不修改公开主命令行为，不出现多分集、全部轨道、语言过滤或覆盖编排。

## 2. 测试先行实现播放器轨道发现

- [ ] 为一个确定 CID 的人工字幕、AI 字幕、混合多轨道和合法空列表编写脱敏 HTTP 固定响应测试。
- [ ] 为缺失字段、错误类型、布尔数值、未知轨道属性、HTTP 状态和平台错误码编写失败测试。
- [ ] 在 Bilibili 适配层集中请求播放器字幕列表并严格映射领域轨道，保持平台顺序和同语言多轨道身份。
- [ ] 将无字幕、需登录、不可访问、网络失败和结构异常映射为稳定且互异的结果。

## 3. 测试先行实现签名 URL 的即时下载

- [ ] 使用唯一伪签名 URL 验证发现后立即以同一个同步 HTTPX Client 请求正文，且不发生缓存、并发或无限重试。
- [ ] 覆盖协议相对 HTTPS URL 的受控补全，以及非 HTTPS、非受信任主机、用户信息和异常端口拒绝。
- [ ] 覆盖 401、403、服务端失败、超时、连接失败、非 JSON 与异常正文结构的分类。
- [ ] 实现基础设施内部的短生命周期句柄，使 URL 不进入领域对象、应用结果、日志、异常或持久化文件。

## 4. 测试先行校验原始 JSON 与字幕片段

- [ ] 用包含额外字段、Unicode、转义、空白和非规范键顺序的响应证明写出的 `.json` 与成功响应字节完全一致。
- [ ] 参数化覆盖缺失片段列表、错误字段类型、NaN/Infinity、负时间、结束早于开始和布尔值冒充数值。
- [ ] 覆盖空格、空正文、内部换行、重叠时间和非单调输入顺序，证明不执行 `strip`、排序、合并或拆分。
- [ ] 实现“原始字节 + 已校验不可变片段”的内部正文结果，解析数据不替代原始字节。

## 5. 测试先行实现忠实 SRT 转换

- [ ] 先为零、小数毫秒边界、`ROUND_HALF_UP`、超过一小时及确定性舍入编写纯函数测试。
- [ ] 锁定条目按输入顺序从 1 编号，时间格式为 `HH:MM:SS,mmm`。
- [ ] 逐字符比较 Unicode、标点、前后空格和多行正文，证明转换器不处理文本。
- [ ] 实现项目内纯 SRT 转换器，不引入第三方字幕、媒体或识别依赖。

## 6. 测试先行实现安全文件发布与 manifest

- [ ] 用临时目录测试 JSON/SRT/manifest 均先写同目录临时文件、关闭后原子替换，并在各种写入失败后清理临时文件。
- [ ] 测试目标已存在时明确失败且不覆盖；跳过、补齐和 `--force` 留待阶段五。
- [ ] 测试 manifest 最后发布，只记录成功发布的相对文件名和视频、分集、轨道身份及结果。
- [ ] 注入各发布步骤故障，证明未完成目标不伪装成功，manifest 失败不删除已完成字幕文件。
- [ ] 实现确定性 UTF-8 manifest，并断言其中无绝对路径、Cookie、请求头、响应正文或签名 URL。

## 7. 组装单分集、单轨道应用闭环

- [ ] 为“确定分集 → 发现轨道 → 明确选择一个轨道 → 即时下载 → JSON/SRT → manifest”编写离线集成测试。
- [ ] 为 AI 字幕固定响应证明生成一一对应的 JSON 与 SRT，并校验 manifest 身份与结果。
- [ ] 覆盖人工字幕、合法无字幕、需登录、不可访问、网络失败、结构异常和导出失败。
- [ ] 使用端口隔离 HTTP 与文件系统细节；应用结果可供阶段五串行编排，但不实现聚合退出码。
- [ ] 回归阶段二分集选择和阶段三认证恢复，确认本阶段不重复登录、不改变选择、不接管公开 CLI。

## 8. 完成安全、质量与合并验收

- [ ] 执行 [`validation.md`](./validation.md) 的全部自动化命令与离线闭环场景。
- [ ] 审计伪 Cookie、伪签名 URL、请求头和响应金丝雀，确认未进入领域、输出、异常、manifest、快照或普通文件。
- [ ] 审计依赖与源码，确认没有媒体下载、ASR、OCR、翻译、私有接口或访问控制绕过。
- [ ] 确认阶段一至三回归通过，分支覆盖率不低于 90%，Ruff、格式与 strict Pyright 通过。
- [ ] 在 Windows 临时目录使用脱敏固定数据人工检查 JSON 字节、SRT 格式、manifest 和故障残留；不执行真实账号提取。
- [ ] 确认 feature spec、实现、测试与锁文件一致，工作区没有无关改动，提交并推送 feature 分支后验证 Windows CI。
