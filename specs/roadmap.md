## 一、实施原则

1. 每个阶段只交付一个可验证增量，避免同时铺开全部模块。
2. 阶段按顺序执行；前一阶段验收通过后，下一阶段才能开始。
3. 每个阶段先补齐测试或验收方式，再实现对应能力。
4. 发现产品或技术决策缺口时，先更新 Constitution，再继续实现。
5. 各阶段只实现当前目标，不提前加入后续范围或 V1 之外的功能。

## 三、阶段定义

### 阶段零：Constitution

**目标：** 建立项目唯一真实来源，消除产品、技术和实施顺序中的关键歧义。

**交付物：**

- `specs/mission.md`
- `specs/tech-stack.md`
- `specs/roadmap.md`

**验收条件：**

- 三份文档均使用简体中文解释所有决策。
- 产品范围、技术栈、架构边界和阶段顺序明确。
- 旧规格不再与 `specs/` 并存为有效来源。

### 阶段一：项目骨架

**目标：** 建立最小工程基础，让后续功能都能在统一结构中实现和测试。

**交付物：**

- Python 3.12+ 与 uv 项目配置。
- `src/bili_subtitle/` 包结构和 `bili-subtitle` 命令入口。
- 主命令及 `auth` 子命令的空行为和完整帮助文本。
- pytest、Ruff、Pyright 和覆盖率检查入口。

**验收条件：**

- `uv run bili-subtitle --help` 可以运行。
- `uv run pytest` 在无网络、无账号环境中通过。
- `uv run ruff check .` 与 Pyright 检查通过。
- 运行时依赖中不存在媒体下载、ASR、OCR 或 GPL 工具依赖。

### 阶段二：输入与元数据

**目标：** 将所有受支持输入稳定解析为一个投稿及有序分集集合。

**交付物：**

- BV、av、完整 URL 和 `b23.tv` 短链解析。
- URL `p`、`--page` 和 `--all-pages` 选择规则。
- 视频、分集和 CID 领域模型。
- Bilibili 元数据适配器及脱敏固定响应测试。

**验收条件：**

- 单分集和多分集投稿都能得到正确的有序分集。
- 参数优先级与互斥规则符合 Mission。
- 无效输入、无效分集和平台异常具有明确结果。
- 不自动扩展到其他 BV 投稿。

### 阶段三：安全登录

**目标：** 让工具在没有手工 Cookie 的情况下取得并复用正常登录状态。

**交付物：**

- Windows Credential Manager 适配器。
- 登录状态检查和 `auth login|status|clear`。
- 终端二维码和扫码轮询状态机。
- 登录成功后恢复原命令的应用流程。

**验收条件：**

- 覆盖未扫码、待确认、成功、过期、取消和失败状态。
- 登录流程具有明确超时，不会无限轮询。
- 重新运行时能够复用有效凭据，失效时自动重新登录。
- 输出、异常和测试快照中不存在 Cookie 或二维码密钥。

### 阶段四：单分集提取闭环

**目标：** 对一个确定分集完成“发现轨道 → 下载正文 → 保存 JSON → 生成 SRT → 写 manifest”。

**交付物：**

- 播放器字幕轨道发现。
- 人工字幕与 AI 字幕轨道模型。
- 临时签名 URL 的即时下载和响应校验。
- 原始 JSON、安全写入、SRT 转换和 manifest。

**验收条件：**

- 一个带 AI 字幕的固定响应可生成对应 JSON 与 SRT。
- SRT 的时间、文字和分段与原始 JSON 一致。
- 无字幕、需登录、不可访问、网络失败和结构异常可以区分。
- 临时签名 URL 不进入领域模型、日志或文件。
- 不存在 ASR、OCR 或媒体下载降级路径。

### 阶段五：完整 V1 流程

**目标：** 把单分集闭环扩展为符合产品契约的完整命令体验。

**交付物：**

- 默认全部分集、指定分集和全部轨道处理。
- 可重复的 `--lang` 过滤。
- Windows 文件名净化、冲突消解和路径长度控制。
- 已有文件逐个跳过、缺失项补齐及 `--force` 覆盖。
- 分集级和轨道级失败隔离、最终摘要与退出码。

**验收条件：**

- 多分集、多语言和同语言多轨道不会互相覆盖。
- 一个分集或轨道失败时，其他项目继续处理。
- 正常完成、部分成功和整体失败分别返回 `0`、`1`、`2`。
- 无字幕和全部跳过作为正常完成处理，并有明确摘要。
- 中断写入不会留下被误认为成功结果的目标文件。

### 阶段六：质量与交付

**目标：** 在 Windows 上完成安全性、可靠性和安装体验验收，交付 V1。

**交付物：**

- 输入、认证、字幕、导出和完整流程的自动化测试矩阵。
- 秘密泄漏、异常响应、重复运行和 Windows 文件系统测试。
- AI 字幕投稿与多分集投稿的显式人工验收记录。
- uv 构建、全局安装和使用说明。

**验收条件：**

- 默认测试不访问网络、不读取真实凭据，并全部通过。
- Ruff、Pyright 和测试覆盖率检查通过。
- 在 Windows 上通过二维码完成真实登录和字幕提取。
- `uv tool install` 后可在新终端调用 `bili-subtitle`。
- 所有 Mission 成功标准均通过。
- 用户文档链接到 `specs/`，没有出现第二套产品或技术定义。

## 四、V1 完成定义

V1 仅在以下条件同时满足时完成：

- 阶段零至阶段六全部通过验收。
- Mission 中的产品契约和不可违背原则均得到实现与测试保护。
- 技术实现符合 Tech Stack 中的依赖方向、安全和测试约束。
- 已知的平台限制被清楚说明，没有通过识别或绕过功能掩盖失败。
