## 一、实施原则

1. 每个阶段只交付一个可验证增量，避免同时铺开全部模块。
2. 阶段按顺序执行；前一阶段验收通过后，下一阶段才能开始。
3. 每个阶段先补齐测试或验收方式，再实现对应能力。
4. 发现产品或技术决策缺口时，先更新 Constitution，再继续实现。
5. V1 已完成能力必须持续回归；V2 不复制或破坏字幕、认证和导出核心。
6. AI 阶段先定义结构化契约和评测，再接真实 Provider；不得以主观“看起来不错”代替验收。
7. 插件保持薄前端，敏感凭据、字幕和生成业务统一留在配对后的本地服务。

## 三、阶段定义

### 阶段零：Constitution

**目标：** 建立项目唯一真实来源，消除产品、技术和实施顺序中的关键歧义。

**交付物：**

- `specs/mission.md`
- `specs/tech-stack.md`
- `specs/roadmap.md`

**验收条件：**

- 三份文档均使用简体中文解释所有决策。
- 产品范围、技术栈、架构边界和阶段顺序明确。
- 旧规格不再与 `specs/` 并存为有效来源。

### 阶段一：项目骨架

**目标：** 建立最小工程基础，让后续功能都能在统一结构中实现和测试。

**交付物：**

- Python 3.12+ 与 uv 项目配置。
- `src/bili_subtitle/` 包结构和 `bili-subtitle` 命令入口。
- 主命令及 `auth` 子命令的空行为和完整帮助文本。
- pytest、Ruff、Pyright 和覆盖率检查入口。

**验收条件：**

- `uv run bili-subtitle --help` 可以运行。
- `uv run pytest` 在无网络、无账号环境中通过。
- `uv run ruff check .` 与 Pyright 检查通过。
- 运行时依赖中不存在媒体下载、ASR、OCR 或 GPL 工具依赖。

### 阶段二：输入与元数据

**目标：** 将所有受支持输入稳定解析为一个投稿及有序分集集合。

**交付物：**

- BV、av、完整 URL 和 `b23.tv` 短链解析。
- URL `p`、`--page` 和 `--all-pages` 选择规则。
- 视频、分集和 CID 领域模型。
- Bilibili 元数据适配器及脱敏固定响应测试。

**验收条件：**

- 单分集和多分集投稿都能得到正确的有序分集。
- 参数优先级与互斥规则符合 Mission。
- 无效输入、无效分集和平台异常具有明确结果。
- 不自动扩展到其他 BV 投稿。

### 阶段三：安全登录

**目标：** 让工具在没有手工 Cookie 的情况下取得并复用正常登录状态。

**交付物：**

- Windows Credential Manager 适配器。
- 登录状态检查和 `auth login|status|clear`。
- 终端二维码和扫码轮询状态机。
- 登录成功后恢复原命令的应用流程。

**验收条件：**

- 覆盖未扫码、待确认、成功、过期、取消和失败状态。
- 登录流程具有明确超时，不会无限轮询。
- 重新运行时能够复用有效凭据，失效时自动重新登录。
- 输出、异常和测试快照中不存在 Cookie 或二维码密钥。

### 阶段四：单分集提取闭环

**目标：** 对一个确定分集完成“发现轨道 → 下载正文 → 保存 JSON → 生成 SRT → 写 manifest”。

**交付物：**

- 播放器字幕轨道发现。
- 人工字幕与 AI 字幕轨道模型。
- 临时签名 URL 的即时下载和响应校验。
- 原始 JSON、安全写入、SRT 转换和 manifest。

**验收条件：**

- 一个带 AI 字幕的固定响应可生成对应 JSON 与 SRT。
- SRT 的时间、文字和分段与原始 JSON 一致。
- 无字幕、需登录、不可访问、网络失败和结构异常可以区分。
- 临时签名 URL 不进入领域模型、日志或文件。
- 不存在 ASR、OCR 或媒体下载降级路径。

### 阶段五：完整 V1 流程

**目标：** 把单分集闭环扩展为符合产品契约的完整命令体验。

**交付物：**

- 默认全部分集、指定分集和全部轨道处理。
- 可重复的 `--lang` 过滤。
- Windows 文件名净化、冲突消解和路径长度控制。
- 已有文件逐个跳过、缺失项补齐及 `--force` 覆盖。
- 分集级和轨道级失败隔离、最终摘要与退出码。

**验收条件：**

- 多分集、多语言和同语言多轨道不会互相覆盖。
- 一个分集或轨道失败时，其他项目继续处理。
- 正常完成、部分成功和整体失败分别返回 `0`、`1`、`2`。
- 无字幕和全部跳过作为正常完成处理，并有明确摘要。
- 中断写入不会留下被误认为成功结果的目标文件。

### 阶段六：质量与交付

**目标：** 在 Windows 上完成安全性、可靠性和安装体验验收，交付 V1。

**交付物：**

- 输入、认证、字幕、导出和完整流程的自动化测试矩阵。
- 秘密泄漏、异常响应、重复运行和 Windows 文件系统测试。
- AI 字幕投稿与多分集投稿的显式人工验收记录。
- uv 构建、全局安装和使用说明。

**验收条件：**

- 默认测试不访问网络、不读取真实凭据，并全部通过。
- Ruff、Pyright 和测试覆盖率检查通过。
- 在 Windows 上通过二维码完成真实登录和字幕提取。
- `uv tool install` 后可在新终端调用 `bili-subtitle`。
- 所有 Mission 成功标准均通过。
- 用户文档链接到 `specs/`，没有出现第二套产品或技术定义。

### 阶段七：V2 Constitution 与兼容基线

**目标：** 在不破坏 V1 的前提下，冻结视频学习助手的产品、技术、安全和兼容边界，并准备后续纵向切片。

**已完成：**

- [x] 决定首个原型面向通用知识视频，接真实字幕和真实云端模型。
- [x] 决定采用“先大纲、章节详情按需生成”的成本与等待策略。
- [x] 决定采用结构化笔记、AI 引导问题、用户回答/复述和证据化反馈。
- [x] 决定本地优先、命名知识库、可移植 Markdown/Obsidian 和用户自备 OpenAI-compatible API。
- [x] 决定公开开源方向使用 Apache-2.0。
- [x] 更新 `mission.md`、`tech-stack.md` 和 `roadmap.md`，真实区分 V1 已完成与 V2 未实现。

**工程基线已完成：**

- [x] 建立 Local API 安全、AI 生成契约、本地存储和兼容命令 ADR。
- [x] 修复无效输入在纯解析前触发登录、非登录中断提示错误和过宽错误分类。

- [x] 添加 `bili-study` 命令骨架、兼容安装验证和 V2 版本策略。

**验收条件：**

- 三份 Constitution、ADR、许可证、命令帮助和实现边界一致。
- V1 全量测试、覆盖率、Ruff、Pyright、构建、归档和隔离安装继续通过。
- `bili-study extract` 与 `bili-subtitle` 对相同输入保持行为和退出码一致。
- 此阶段不得声称插件、本地服务、模型或学习指南已经可用。

### 阶段八：学习数据与 AI 后端

**目标：** 把现有字幕结果提升为可持久、可引用、可分块和可供学习功能复用的单视频知识来源。

**交付物：**

- 版本化 `TranscriptRevision`、cue、`EvidenceRef`、`StudyGuide`、章节、问题、笔记和复述模型。
- 命名知识库注册、本地 SQLite migration、任务状态和可重建缓存。
- Provider 配置命令、Credential Manager API Key、OpenAI-compatible Chat 适配器。
- 完整字幕 Map/Reduce 大纲、按需章节详情、结构修复和证据校验。
- 个人 Markdown 笔记与可重建生成 Markdown 的分离发布。

**验收条件：**

- 短字幕和超长字幕都覆盖完整 cue 范围，不直接截断视频尾部。
- 任何章节、问题和反馈引用都能映射到当前 Transcript revision 的合法 cue 和时间范围。
- 相同生成指纹命中缓存；显式重新生成不覆盖个人笔记。
- Provider 超时、认证、配额、结构和引用错误使用稳定分类且不泄漏响应或 Key。
- 默认测试通过固定响应完成，不访问真实 Bilibili、模型或 Credential Manager。

### 阶段九：Chrome/Edge 视频学习原型

**目标：** 通过真实 Bilibili 字幕和真实云端模型，完成用户主动控制的单视频学习侧栏闭环。

**交付物：**

- 只绑定 `127.0.0.1` 的 FastAPI Local API、持久 job、OpenAPI 和 TypeScript client。
- 五分钟单次配对码、扩展 Origin 绑定、Bearer token、Host/Origin/CORS 校验。
- WXT + TypeScript + React Manifest V3 扩展及 Chrome/Edge 构建。
- 当前 BV/P/播放时间识别、字幕轨道选择、章节跟随和证据跳转。
- 学习大纲、按需章节详情、结构化时间戳笔记、引导问题和回答/复述反馈。
- 可移植 Markdown 输出与服务重启后的状态恢复。

**验收条件：**

- 用户可按文档完成知识库创建、Provider 配置、Bilibili 登录、服务启动和扩展配对。
- 打开支持的视频页后，用户主动生成真实学习大纲；插件不自动暂停或发起模型请求。
- 多字幕轨道允许选择，单轨道可直接使用；无字幕与访问失败明确区分。
- 用户笔记刷新和服务重启后仍存在，重新生成不会覆盖。
- AI 反馈只显示通过引用校验的内容，点击证据回看误差不超过两秒。
- Chrome 与 Edge 的模拟 E2E、真实脱敏验收和全部 V1 回归通过。

**发布边界：** `0.2.0-alpha`，只提供仓库构建与“加载已解压扩展”，不进入扩展商店。

### 阶段十：视频学习助手 MVP

**目标：** 根据至少五次完整视频学习记录加固原型，使其达到公开开源个人工具的可安装标准。

**交付物：**

- 任务取消、恢复、显式重试、缓存管理、用量与成本提示。
- 章节主动回忆小测、学习总结和基础 Mermaid/Markmap 导图。
- 侧栏信息密度、错误恢复、无障碍和长视频体验改进。
- 安装、升级、数据迁移、隐私、故障排查和模型兼容文档。
- Python 双命令发行和 Chrome/Edge 可复现构建归档。

**验收条件：**

- 五次原型学习记录形成明确问题清单，并全部关闭或接受为已知限制。
- 任务失败或模型切换不破坏 Transcript、个人笔记和已有有效生成物。
- 小测与导图复用同一证据模型，不另建无法核验的 Prompt 孤岛。
- Python 与扩展两套 CI、依赖/许可证、安全和归档审计通过。

**发布边界：** `0.2.0` 本地安装 MVP；扩展商店发布仍需独立安全与隐私阶段。

### 阶段十一：复习闭环

**目标：** 把一次观看产生的笔记、回答和薄弱点转化为可持续复习任务。

**交付物：**

- 知识点卡片、错题、用户置信度、复述遗漏和回看片段。
- 用户主动启动的间隔复习队列、复习历史和完成状态。
- Markdown 与 Anki 兼容导出；导出不成为用户数据的唯一副本。

**验收条件：**

- 复习先要求用户回忆，再显示答案和证据。
- 答错或低置信度项目能够跳回原 BV/P/时间范围。
- 重新生成学习指南不会重置用户复习记录。

### 阶段十二：跨视频知识库

**目标：** 在稳定的单视频学习数据之上，为几十到数百个视频提供本地跨视频检索和证据化问答。

**交付物：**

- 一个或多个 URL/文本清单的显式批量入库、去重、删除和索引重建。
- 独立 Embedding Provider 配置、上传提示、批处理和本地向量缓存。
- SQLite FTS5 + 可替换向量端口的混合检索；首个实现锁定 `sqlite-vec`。
- 跨视频搜索、来源问答、观点比较和浏览器中的相关旧知识提示。

**验收条件：**

- 首次 Embedding 前明确提示全部字幕分块将发送至用户配置的服务。
- 固定问题集能够召回正确视频与片段；回答只引用检索到的有效证据。
- `sqlite-vec` 索引可删除重建，pre-v1 表结构不进入公共 schema。
- 新增一个视频只处理新增或失效内容，不全库重算。

### 阶段十三：生态候选

**目标：** 只在前述阶段形成真实使用证据后，评估更重的采集、客户端和同步能力。

**候选项：**

- 收藏夹、合集和 UP 主增量同步。
- 先修知识、课程学习路径和跨视频矛盾观点。
- Obsidian 专用插件、桌面客户端和浏览器商店发布。
- 可选本地 Embedding、跨设备加密同步和恢复协议。

本阶段没有承诺版本和排期。任何候选进入实施前必须先形成独立需求、隐私评估和验收矩阵。

## 四、完成定义

### V1 完成定义

V1 仅在以下条件同时满足时完成：

- 阶段零至阶段六全部通过验收。
- Mission 中的产品契约和不可违背原则均得到实现与测试保护。
- 技术实现符合 Tech Stack 中的依赖方向、安全和测试约束。
- 已知的平台限制被清楚说明，没有通过识别或绕过功能掩盖失败。

上述条件已经满足；V1 完成状态不因 V2 规划而撤销。

### V2 当前完成定义

- 产品形态、首个用户场景、交互原则、模型方式、本地数据、Obsidian、命名、开源许可和阶段顺序已经确定。
- 阶段七的 Apache-2.0 文件、ADR、核心整改、导出端口、`bili-study extract|auth`、双入口发行与兼容迁移已经实现并通过验收。
- 阶段八的 Transcript、证据、知识库、Provider、两阶段指南、按需详情和个人 Markdown 工程已经实现并通过离线门禁；真实 Provider 与合并 CI 尚待验收。
- 阶段九的 Local API、配对安全和浏览器插件仍未实现。
- 只有每个阶段的交付物、自动化、脱敏真实验收、文档和兼容门禁全部通过，才能将该阶段改为“已完成”。
