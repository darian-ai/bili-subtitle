# 阶段六：质量与交付实施计划

> 实施状态（2026-08-21）：任务组 1—8 全部完成；最终独立审计修复、真实平台脱敏验收及待合并提交 Windows CI 均通过。

## 1. 建立契约—测试追踪矩阵

- 枚举 Mission 成功标准、不可违背原则、V1 命令与输出契约及 Tech Stack 工程约束。
- 将每项要求映射到现有直接测试、需新增的自动化测试或显式人工验收。
- 补齐输入、认证、字幕、导出和完整流程的缺口，确保默认测试完全离线。
- 每次新增测试后运行相关测试组并提交。

## 2. 强化安全、异常与 Windows 回归

- 扩展统一秘密金丝雀测试，覆盖输出、异常、对象表示、manifest、路径、归档和失败诊断。
- 参数化异常 HTTP 状态、平台错误码、截断/错误类型/超大或畸形结构、网络超时和认证失效。
- 完整验证重复运行、缺项补齐、`--force`、局部失败及所有原子写入故障。
- 在 Windows 语义下复核非法名、冲突、长路径、不可写目录和临时文件清理。
- 运行全量质量门禁并提交。

## 3. 完成 README 与交付说明

- 新建只面向安装和使用的 README，链接三份 Constitution。
- 写明 uv 安装、认证、主命令、常见结果、更新/卸载和开发验证命令。
- 审核 README 没有形成第二套产品、技术或路线定义，没有真实数据及秘密。
- 验证文档命令与实际 CLI 帮助一致后提交。

## 4. 验证构建产物

- 从干净 `dist/` 运行 `uv build`，确认恰有预期 wheel 与 sdist。
- 自动检查归档文件清单、项目元数据、Python 要求、依赖及控制台入口。
- 从归档中搜索缓存、覆盖率、凭据、字幕输出、临时文件及秘密金丝雀。
- 增加可重复的构建/归档验证入口并提交，不提交生成的 `dist/` 产物。

## 5. 验证隔离 uv 工具安装

- 创建并解析临时 `UV_TOOL_DIR`、`UV_TOOL_BIN_DIR`，确认位于本阶段临时根目录。
- 从本地 wheel 安装，不读取或修改用户默认全局工具状态。
- 启动新 PowerShell 进程，在仓库外目录通过隔离 `PATH` 运行命令帮助并检查退出码。
- 清理经过绝对路径校验的隔离目录，记录脱敏结果并提交。

## 6. 完成全依赖与禁止能力审计

- 审查直接、传递、开发和构建依赖及 wheel/sdist 元数据一致性。
- 审查依赖方向、网络入口、文件写入入口和凭据边界。
- 搜索并人工判断全部禁止能力；对误报记录原因，对真实问题修复并补测试。
- 将审计结果追加至 validation，不复制 Constitution 定义，运行回归并提交。

## 7. 执行真实平台人工验收

- 在 Windows 上使用正常二维码流程确认登录和凭据复用。
- 对含 AI 字幕的普通 UGC 投稿执行完整提取并检查 JSON/SRT/manifest。
- 对多分集普通 UGC 投稿验证默认全部、`--page N`、重复跳过及 `--force`。
- 验证摘要、退出码、文件身份和文本忠实性；清理测试输出时只处理明确的验收目录。
- 仅记录脱敏状态，不记录账号、投稿标识、字幕正文或任何秘密，并提交验收记录。

## 8. 扩展 CI 并完成发布候选审计

- 让 Windows CI 在锁定环境中执行 pytest、Ruff、格式、strict Pyright、构建、归档检查和隔离安装检查。
- 保持 CI 不联网访问 Bilibili、不读取真实凭据；仅依赖安装和本地产物构建可联网。
- 在待合并提交上取得成功 CI 证据，记录 run 链接和提交哈希。
- 逐项审计 requirements、validation、Mission 成功标准和路线验收条件；修复所有缺口并每次提交。
- 确认工作区只含阶段六预期改动，形成最终可合并结论。
