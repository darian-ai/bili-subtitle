# 阶段六：质量与交付需求

## 范围

本阶段把阶段一至五已经实现的 V1 行为提升到可发布状态，不改变
[`mission.md`](../mission.md) 的产品契约，也不新增产品能力。交付范围包括：

- 建立输入、认证、字幕、导出和完整流程的可追溯自动化测试矩阵，补齐当前测试未直接证明的边界。
- 覆盖秘密泄漏、异常平台响应、重复运行及 Windows 文件系统的集成与回归测试。
- 在 Windows 上显式人工验收真实 AI 字幕投稿和真实多分集普通 UGC 投稿。
- 使用 `uv build` 生成 wheel 和 sdist，检查两类归档的元数据、入口和文件清单。
- 从本地 wheel 在隔离的 uv 工具目录安装，并在新 PowerShell 进程调用 `bili-subtitle`。
- 提供 README 使用说明并链接 Constitution；README 不复制或改写产品与技术定义。
- 审计全部直接、传递和构建依赖，以及源码中的禁止能力。
- 逐项证明 Mission 的成功标准、不可违背原则及阶段六路线验收条件。
- 扩展 Windows CI，使待合并提交自动执行质量、构建和隔离安装门禁。

## 上下文

- 阶段一至五已经完成，现有测试覆盖输入解析、元数据、登录、轨道发现、原始 JSON、SRT、
  manifest、完整多分集流程、重复运行、Windows 路径和局部失败。
- 默认自动化必须保持离线，不访问真实网络、不读取真实 Credential Manager、不等待真实时间。
- 真实平台接口不稳定，人工验收只证明当前正常网页权限下的端到端行为，不把实时响应固化为测试数据。
- 当前项目使用 Python 3.12+、uv、Hatchling、Typer、Rich、HTTPX、keyring、qrcode、pytest、
  Ruff 和 Pyright；阶段六不得借交付之名改变该技术栈。
- 当前仓库没有 README；现有 Windows CI 尚未执行构建、归档检查或隔离工具安装。

## 已确定决策

### 自动化矩阵与可追溯性

1. 用一份集中矩阵把 Mission 契约映射到直接测试；已有充分测试可复用，不以重复测试数量代替证据。
2. 默认测试必须通过 HTTP、凭据、时钟、二维码和文件系统替身封锁外部状态；任何未拦截网络均失败。
3. 测试至少覆盖：四种输入、分集优先级、认证全部终态与一次恢复、人工/AI/同语言多轨道、
   原始 JSON 与 SRT 忠实性、manifest、无字幕/不可访问/网络/结构异常、局部失败及 `0|1|2` 退出码。
4. 安全金丝雀同时检查 stdout、stderr、异常、`repr`、日志、manifest、路径、构建归档和测试诊断；
   不依赖单纯事后字符串替换作为保护。
5. Windows 文件系统矩阵继续覆盖非法字符、保留名、尾随字符、大小写冲突、长路径、原子替换、
   临时清理及现有文件保护，并增加打包安装后的实际工作目录运行检查。

### 真实平台人工验收

1. 只使用用户确认可公开操作的普通 UGC 投稿及当前账号正常可见字幕，不测试番剧、付费、地区、
   会员、风控或其他访问控制绕过。
2. AI 投稿至少验证一次主命令端到端生成每条所选轨道的 JSON、SRT 和 manifest；人工抽查字幕原文、
   标点、空格、分段和时间对应关系，不在记录中保存字幕正文。
3. 多分集投稿依次验证：未指定分集默认全部、`--page N` 单页、重复运行默认逐文件跳过、
   `--force` 覆盖。还要核对 P 序号、轨道身份、摘要和退出码。
4. 人工记录只包含日期、Windows/Python/uv 版本、使用的命令形态、脱敏场景、退出码和通过/失败状态。
   不记录账号名、UID、Cookie、二维码或密钥、请求头、响应正文、字幕内容、投稿标识及签名 URL。
5. 人工验收不得把真实凭据复制到仓库、命令行参数或环境变量；沿用 Windows Credential Manager。

### 构建与隔离安装

1. `uv build` 必须生成一个 wheel 和一个 sdist；从干净 `dist/` 开始，归档检查不得依赖工作区源码导入。
2. 检查两类归档只包含发布所需源码、元数据和文档，不含测试缓存、覆盖率文件、凭据、生成字幕、
   临时文件或签名 URL；wheel 必须声明 `bili-subtitle` 控制台入口及正确运行时依赖。
3. 安装验证使用临时、隔离的 `UV_TOOL_DIR` 和 `UV_TOOL_BIN_DIR`，从本地 wheel 执行
   `uv tool install`；不得查询或修改用户默认全局工具目录。
4. “新终端可调用”由一个全新的 PowerShell 进程证明：仅把隔离 bin 目录加入该子进程 `PATH`，
   在仓库外临时目录运行 `bili-subtitle --help`。不得用 `uv run`、当前虚拟环境或仓库源码代替。
5. 验证结束删除的仅是本阶段创建且绝对路径已核实的临时目录；不得执行全局 `uv tool uninstall`。

### README 与唯一真实来源

1. README 只包含项目简介、系统要求、uv 安装、命令使用示例、输出位置入口、常见结果提示、
   卸载/升级方式和开发质量命令。
2. README 必须链接 `specs/mission.md`、`specs/tech-stack.md`、`specs/roadmap.md`，并明确这些文件是
   产品、技术与阶段状态的唯一权威来源。
3. README 不另列完整产品范围、错误码规范、架构、依赖决策或路线状态；发现需要新增定义时先修改 Constitution。
4. 示例不得包含真实投稿、账号、Cookie、二维码、签名 URL 或声称绕过限制的内容。

### 依赖、禁止能力与发布边界

1. 审计 `pyproject.toml`、`uv.lock`、wheel/sdist 元数据及完整传递依赖树，解释每个直接运行时依赖的用途。
2. 搜索源码、脚本、CI、文档和归档，确认不存在媒体/音频/封面下载、FFmpeg、ASR、OCR、翻译、
   浏览器自动化、WBI、APP 私有接口、访问控制绕过、异步框架、任务队列、数据库或插件系统能力。
3. 依赖审计以“是否赋予禁止能力”和实际调用路径为准；不能仅依赖包名搜索。发现冲突时先修复或更新 Constitution。
4. V1 交付仅为标准 Python wheel/sdist 与 `uv tool install` 使用方式；不发布到包索引、不创建 GitHub Release、
   不构建 EXE、不加入自动更新，除非用户另行授权且 Constitution 先更新。

## 非目标

- 不新增自定义输出目录、批量投稿、GUI、插件、并发下载或平台绕过。
- 不修改字幕文本，不增加 ASR、OCR、翻译或媒体下载降级路径。
- 不把真实网络人工场景加入默认 pytest 或 CI。
- 不操作用户既有全局 uv 工具、默认凭据槽位之外的数据或发布平台状态。
