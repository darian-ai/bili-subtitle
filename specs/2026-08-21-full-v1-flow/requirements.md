## 背景与目标

阶段二已把输入解析为一个普通 UGC 投稿及有序分集，阶段三已提供安全且可恢复一次的认证闭环，阶段四已验证单分集、单轨道的发现、下载、忠实转换与原子发布。本阶段把这些内部能力接入公开主命令，按 Mission 一次完成多分集、全部轨道、语言过滤、Windows 文件策略、局部失败隔离、汇总与退出码契约。

本阶段完成的是离线固定响应可证明的完整 V1 命令流程；阶段六仍负责扩大自动化矩阵、真实 Windows 投稿人工验收、安装、构建和用户文档交付。

## 范围

- 公开主命令执行“输入与元数据 → 有效认证 → 所选分集 → 所选轨道 → 导出 → manifest → 摘要”。
- 保持 URL `p`、`--page`、`--all-pages` 的既有优先级；无任何分集提示时默认处理全部分集。
- 每个分集发现并按平台顺序处理全部可见轨道；可重复 `--lang` 按平台语言代码过滤。
- 为默认输出树实现确定性的 Windows 文件名净化、保留名处理、冲突消解与路径长度控制。
- 已有 JSON/SRT 逐文件跳过，只补齐缺失项；`--force` 才覆盖已存在目标。
- 分集和轨道串行处理并隔离失败；输出逐项结果、最终摘要和 `0|1|2` 退出码。
- 多分集、多语言及同语言多轨道写入一个安全、确定性的投稿级 `manifest.json`。
- 沿用阶段四原始 JSON、忠实 SRT、签名 URL 隔离及同目录临时文件原子发布语义。

## 公开命令与选择契约

```text
bili-subtitle <视频标识或URL> [--page N | --all-pages] [--lang 语言代码]... [--force]
```

- `--page` 与 `--all-pages` 仍互斥；显式选项覆盖 URL `p`；默认无提示时选择全部分集，不改变阶段二规则。
- `--lang` 可重复。每个值必须是非空的平台语言代码；按精确、区分大小写的代码匹配，重复值去重但保持用户首次给出的顺序，不造成轨道重复处理。
- 未给 `--lang` 时选择每个分集的全部可见轨道。给出过滤器后，仍按播放器返回顺序处理匹配轨道；同语言、同名称轨道不得去重，轨道 ID 始终保留身份。
- 一个分集没有可见轨道，或过滤后没有匹配轨道，均为该分集的正常“无字幕/无匹配字幕”结果，不发起正文请求。
- 全流程使用一个同步 HTTPX Client 和同一已验证会话，分集、轨道均串行，不引入并发。

## 认证接入

- 主命令解析参数后创建一次应用流程；读取并验证已有凭据，有效时直接继续。
- 无凭据或凭据失效时沿用阶段三二维码状态机；成功后向同一 Client 应用会话并从认证检查之后恢复原任务恰好一次，不重新要求用户执行命令，也不重复元数据/导出副作用。
- 二维码过期、取消、认证网络失败或凭据保存失败时，整体失败并返回 `2`，不得进入字幕循环。
- Cookie、二维码密钥、请求头和带签名字幕 URL 不得进入 CLI 输出、异常、manifest、文件名或普通文件。

## 输出树与 Windows 文件策略

默认输出为：

```text
当前工作目录/subtitles/视频标题 [BV号]/
  P01-分集标题.语言.轨道ID.json
  P01-分集标题.语言.轨道ID.srt
  manifest.json
```

- 文件名组件净化必须确定：替换 Windows 非法字符 `< > : " / \\ | ? *` 和 C0 控制字符，移除尾随空格与句点；空组件使用稳定占位名。
- 对大小写不敏感的 Windows 保留名 `CON`、`PRN`、`AUX`、`NUL`、`COM1`—`COM9`、`LPT1`—`LPT9`（含扩展名前的基名）加稳定前缀，不能依赖当前操作系统拒绝。
- P 序号使用至少两位十进制并保留真实序号；语言和轨道 ID 都参与文件名。净化后发生大小写不敏感冲突时，以稳定身份摘要后缀消解，结果不依赖运行顺序。
- 输出根与投稿目录同样应用净化。路径规划在网络正文请求和任何发布前完成；每个最终绝对路径预留临时文件后缀空间并限制在 240 个字符以内。超长时只截断可读标题组件，并加入稳定摘要；不得截断扩展名、P 序号、语言、轨道身份或冲突后缀。
- 无法在预算内生成唯一、安全路径时，将对应轨道分类为导出失败，继续其他项目；不得静默写到另一个投稿或工作目录外。
- manifest 只记录投稿目录内相对文件名，不记录绝对路径。

## 已有文件、补齐与 `--force`

- 默认模式分别检查每个轨道的 `.json` 和 `.srt`：两者都存在则两项跳过；只存在一个时保留其字节，仅发布缺失项；都不存在时发布两项。
- 需要补齐任一项时重新即时下载并严格校验一次字幕正文；只将下载结果用于缺失目标，绝不以补齐为理由覆盖已有文件。缺失 SRT 从本次校验正文生成，缺失 JSON 保存本次原始响应字节。
- `--force` 对选中轨道的 JSON/SRT 均重新下载并原子替换；任一新内容准备或临时写入失败时，原目标保持不变。覆盖不删除不再被选择的旧文件。
- 每个文件记录 `written`、`replaced` 或 `skipped`；轨道只有在所需目标均已存在或成功发布时才是有效结果。
- manifest 每次在所有项目处理后由完整本次结果重新构建并最后原子替换；失败时保留旧 manifest 和已成功发布的字幕文件，并记为导出失败。
- 不以目标文件存在直接证明内容有效；本阶段不擅自修改已有文件，但 manifest 明确记录其为跳过而非本次校验成功。

## 原子性与失败隔离

- JSON、SRT 和 manifest 分别通过同目录唯一临时文件写入、刷新、关闭后原子替换；无论创建、编码、写入、刷新或替换失败，都清理临时文件。
- 需要同时发布 JSON/SRT 时先完整准备两者；单个目标发布失败不得留下该目标的部分内容，已成功发布的兄弟文件可以保留并在摘要中真实反映。
- 分集轨道发现失败只终止该分集；一个轨道的下载、结构或导出失败只终止该轨道。后续分集和轨道继续。
- 认证整体失败、输入/元数据/分集选择失败、无法建立投稿输出上下文等命令级错误不进入逐项循环。
- 不因后续失败删除先前成功、补齐、覆盖或既有跳过文件；不使用事务回滚掩盖局部成功。

## manifest 与结果摘要

- manifest 扩展阶段四身份字段，包含 schema 版本、投稿身份、每个所选分集及其轨道、语言/类型、相对 JSON/SRT 文件名、逐文件动作和轨道结果；顺序与分集、轨道处理顺序一致。
- 无字幕、无匹配字幕、分集失败和轨道失败均以稳定分类记录；失败信息不包含远端响应正文、URL、Cookie、请求头或绝对路径。
- 终端逐项输出使用简体中文稳定分类，标题等不可信文本必须进行终端安全展示；最终摘要至少计数：分集、轨道、写入、覆盖、跳过、无字幕/无匹配及失败。
- 摘要必须明确区分“没有字幕”“语言过滤无匹配”“全部已有文件跳过”和真正失败，不以进度显示替代最终结果。

## 退出码聚合

- `0`：命令正常完成且没有失败；包括产生新文件、覆盖/补齐、全部文件跳过、所有分集无字幕或过滤后全部无匹配。
- `1`：至少一个轨道形成有效结果（写入、覆盖、补齐或完整跳过），同时至少一个分集/轨道/manifest 失败；无字幕或无匹配本身不算失败。
- `2`：命令级失败，或逐项处理结束后存在失败且没有任何有效轨道结果。认证、输入、元数据和分集选择失败始终为 `2`。
- manifest 失败参与失败计数；若已有有效轨道则为 `1`，否则为 `2`。纯无字幕/无匹配且 manifest 成功仍为 `0`。

## 已确定决策

1. 阶段五一次替换公开主命令的元数据摘要占位，不能发布只处理首分集或首轨道的临时行为。
2. 语言过滤精确匹配平台代码；轨道输出顺序始终来自平台，不按用户过滤值重排。
3. 文件身份同时包含 P 序号、语言和轨道 ID；净化冲突用源身份稳定摘要消解，不使用依赖目录现状的递增编号。
4. 缺失补齐重新下载正文，但只发布缺失目标；这样保留既有文件并维持阶段四对新 SRT/JSON 来源的严格校验。
5. `--force` 表示允许原子替换所选 JSON/SRT 和本次 manifest，不表示清空目录或删除非本次文件。
6. 无字幕、无匹配和全跳过是正常结果；只有真实失败参与 `1|2` 聚合。
7. manifest 是本次命令的投稿级结果快照，最后原子替换；不会保存秘密、签名 URL、绝对路径或响应正文。

## 不在范围内

- 阶段六的真实账号 AI 字幕投稿、多分集投稿、重复运行和 `--force` 人工验收矩阵。
- 扩大为发布级完整测试矩阵、Windows CI 最终发布验收、覆盖率补强专项。
- `uv build`、`uv tool install`、新终端全局调用、README/用户文档与发布说明。
- 自定义输出目录、配置文件、结构化机器输出、并发、断点续传、缓存或数据库。
- 多投稿、合集、番剧、影视、课程、互动视频或批量 URL。
- 媒体下载、ASR、OCR、翻译、润色、双语合并、私有接口或访问控制绕过。

## 安全与架构约束

- CLI 只解析参数、渲染结构化结果并映射退出码；不直接请求字幕接口、读 Cookie 或写文件。
- 应用层串行编排阶段二至四端口；领域层保持标准库依赖，不导入 Typer、Rich、HTTPX、keyring 或平台实现。
- 默认测试无网络、无真实凭据、无真实等待，所有输出使用 pytest 临时目录和明显伪数据。
- 用伪 Cookie、二维码密钥、签名 URL、响应正文与绝对路径金丝雀审计输出、异常、`repr`、manifest、文件名和提交内容。
- 不新增媒体、识别、浏览器自动化、异步、数据库或绕过依赖；V1 保持同步串行处理。
