# 阶段五：完整 V1 流程验证及合并标准

## 自动化质量门禁

在仓库根目录依次运行：

```powershell
uv sync --locked --dev
uv run pytest
uv run ruff check .
uv run ruff format --check .
uv run pyright
git diff --check
```

全部命令必须返回 `0`。pytest 必须在无网络、无账号、无真实 Credential Manager、无真实等待环境通过，分支覆盖率不低于 90%。待合并提交的 Windows GitHub Actions 必须运行相同质量检查并通过。

## 分集、轨道与语言过滤矩阵

| 场景 | 期望证据 |
|---|---|
| 无分集提示的多分集投稿 | 按平台顺序处理全部分集 |
| URL `p=N` | 只处理 P=N |
| `--page N` | 只处理 P=N，并按既有规则覆盖 URL `p` |
| `--all-pages` | 处理全部分集，并按既有规则覆盖 URL `p` |
| 未给 `--lang` | 每个分集按平台顺序处理全部可见轨道 |
| 重复 `--lang zh-CN --lang en-US` | 精确匹配两种代码，不按过滤值重排轨道 |
| 同一语言值重复 | 去重过滤条件，不重复处理同一轨道 |
| 同语言多个轨道 | 全部保留，轨道 ID 与输出文件各自唯一 |
| 合法空轨道集合 | 记录无字幕，不下载正文，不算失败 |
| 过滤后空集合 | 记录无匹配字幕，不下载正文，不算失败 |

测试必须证明一次命令只处理一个投稿，全部循环同步串行，使用同一个 Client 和同一已验证会话。

## Windows 文件系统矩阵

- 参数化覆盖 `< > : " / \\ | ? *`、C0 控制字符、尾随空格/句点、空标题和 Unicode。
- 参数化覆盖大小写变体及带扩展形式的 `CON`、`PRN`、`AUX`、`NUL`、`COM1`—`COM9`、`LPT1`—`LPT9`。
- 构造净化后相同、仅大小写不同、同语言同名称不同轨道 ID 的输入，证明路径在 Windows 大小写不敏感语义下唯一且确定。
- 构造长工作目录、长视频标题、长分集标题、语言及轨道 ID，证明每个最终绝对路径（含临时后缀预算）不超过 240 字符，且扩展名、P 序号和稳定身份未丢失。
- 相同输入在空目录和已有无关文件目录中得到相同规划；无法安全规划时对应轨道明确失败，不写到根目录外。
- 所有 manifest 文件名都是投稿目录内相对路径，不出现盘符、UNC 或绝对路径。

## 重复运行、补齐与覆盖矩阵

| JSON | SRT | `--force` | 期望结果 |
|---|---|---:|---|
| 不存在 | 不存在 | 否 | 下载一次，原子发布两项，记录 `written` |
| 存在 | 存在 | 否 | 不下载，两项 `skipped`，原字节不变 |
| 存在 | 缺失 | 否 | 下载并校验一次，只补 SRT；JSON 原字节不变 |
| 缺失 | 存在 | 否 | 下载并校验一次，只补原始 JSON；SRT 原字节不变 |
| 任意 | 任意 | 是 | 下载一次，准备新内容后原子写入/替换两项，记录 `replaced` 或 `written` |

- 注入下载、校验、临时创建、编码、写入、刷新、关闭和替换失败，证明无部分目标或临时文件伪装成功。
- `--force` 替换失败时旧目标保持原字节；默认补齐失败时既有兄弟文件保持原字节。
- 全部已有文件跳过不请求字幕正文，摘要明确“全部跳过”，退出码为 `0`。
- `--force` 不删除未选择轨道、旧分集或其他投稿文件。

## 分集与轨道失败隔离

| 故障位置 | 期望结果 |
|---|---|
| 一个分集轨道发现失败 | 记录该分集失败，继续后续分集 |
| 一个分集无字幕 | 记录正常结果，继续后续分集 |
| 一个轨道正文网络失败 | 只终止该轨道，继续同分集后续轨道 |
| 一个轨道需登录或不可访问 | 分类明确，不绕过，继续其他项目 |
| 一个轨道正文结构异常 | 不发布该轨道的新目标，继续其他项目 |
| 一个轨道路径或导出失败 | 保留其他成功/既有文件，继续其他项目 |
| manifest 发布失败 | 保留旧 manifest 和全部字幕文件，摘要记录失败 |

调用顺序、结果顺序、manifest 顺序和摘要计数必须由离线流程测试锁定。后续失败不得删除先前成功结果。

## 摘要与退出码矩阵

| 结果集合 | 退出码 | 期望摘要 |
|---|---:|---|
| 全部写入/补齐/覆盖成功 | 0 | 各动作计数准确，无失败 |
| 全部目标已存在并跳过 | 0 | 明确全部跳过，无失败 |
| 所有分集无字幕 | 0 | 明确无字幕，不称为错误 |
| 语言过滤后全部无匹配 | 0 | 明确无匹配，不称为错误 |
| 至少一个有效轨道且另有失败 | 1 | 成功/跳过与失败分别计数、分类 |
| 有失败且无有效轨道 | 2 | 明确整体未产生有效轨道结果 |
| 输入、元数据、选择或认证失败 | 2 | 循环前终止，不创建伪成功输出 |
| manifest 失败且已有有效轨道 | 1 | 字幕文件保留，manifest 失败可见 |

逐项输出和摘要中的不可信标题必须进行终端控制字符安全处理。CLI 测试必须断言无 traceback、远端正文或秘密。

## manifest 验证

- schema 版本、投稿 bvid/aid/标题、所选分集身份和轨道身份类型稳定。
- 轨道按分集与平台顺序记录；同语言多轨道不去重，文件名不冲突。
- 每个文件动作准确记录 `written`、`replaced` 或 `skipped`；无字幕、无匹配和分类失败可区分。
- JSON/SRT 仅为安全相对文件名；不包含绝对路径、Cookie、二维码、请求头、播放器/正文响应或签名 URL。
- manifest 在全部轨道后由完整本次结果确定性生成，通过同目录临时文件原子替换；故障不破坏旧 manifest。
- 摘要计数与 manifest 中的本次结果逐项一致。

## 认证恢复与安全验证

- 有效伪凭据只验证一次并用于同一 Client，随后直接完成多分集流程。
- 缺失或失效伪凭据只启动一次二维码状态机；成功保存、应用后恢复原任务一次，不重复已完成的元数据或文件动作。
- 过期、取消、登录网络失败和凭据保存失败返回 `2`，不进入字幕处理。
- 以唯一伪 Cookie、二维码密钥、签名 URL、响应正文和绝对路径为金丝雀，检查 stdout、stderr、异常、`repr`、manifest、字幕文件名、测试快照和提交内容均不泄漏。
- 临时签名 URL 仍只在基础设施层调用栈中短暂存在并立即使用，不进入应用/领域结果。

## Windows 离线检查

在 Windows 新建脱敏临时目录，以固定响应运行完整流程：

1. 检查多分集、多语言和同语言多轨道目录树、净化结果、唯一性及路径长度。
2. 重复运行确认全跳过，再分别删除一项确认缺失补齐，最后以 `--force` 确认旧目标被安全替换。
3. 注入分集和轨道故障，确认其他结果保留、摘要/manifest 分类及退出码正确。
4. 注入每个发布故障并检查无临时残留、无部分文件伪成功、旧目标不损坏。
5. 检查终端、manifest 和文件名中不存在伪秘密、签名 URL、响应正文或绝对路径。

本阶段不执行或记录真实账号、真实 AI 字幕投稿或真实多分集投稿结果；该显式人工矩阵属于阶段六。
