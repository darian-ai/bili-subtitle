# 阶段三：安全登录验证及合并标准

## 自动化验证

在仓库根目录依次运行：

```powershell
uv sync --locked --dev
uv run pytest
uv run ruff check .
uv run ruff format --check .
uv run pyright
```

全部命令必须返回 `0`。pytest 必须在无网络、无账号环境通过，分支覆盖率不低于 90%，且不得读取真实 Credential Manager 或发生真实等待。Windows GitHub Actions 必须运行同一组质量检查。

## 凭据存储场景

| 场景 | 期望结果 |
|---|---|
| 默认槽位没有凭据 | 返回未找到，不抛出后端异常，不访问网络 |
| 保存后再次读取 | 严格恢复等价会话凭据；使用固定服务名与默认槽位 |
| 清除已有凭据 | 删除成功，随后读取为未找到 |
| 清除不存在的凭据 | 幂等成功，不伪造错误 |
| 非法 JSON、未知版本或错误字段类型 | 返回凭据无效，不把原文放入错误消息 |
| keyring 后端读取、保存或删除失败 | 返回对应存储错误，不报告未登录、登录成功或清除成功 |

单元和流程测试必须替换 keyring 后端。真实 Windows Credential Manager 验收使用专用测试槽位，结束后清除，不得读取或覆盖用户默认槽位中的现有凭据。

## 认证适配器与状态机场景

| 状态或故障 | 期望结果 |
|---|---|
| 未扫码 → 待确认 → 成功 | 按状态变化提示；校验并保存凭据后返回成功 |
| 多次未扫码后成功 | 按固定间隔有界轮询，不按每次响应刷屏 |
| 二维码过期 | 明确终止，不自动无限申请新二维码，不保存凭据 |
| 平台报告取消或失败 | 返回对应终止结果，不保存凭据 |
| 用户按 `Ctrl+C` | 无堆栈地返回取消，不覆盖已有凭据 |
| 达到总超时 | 明确返回超时，轮询次数受控 |
| 瞬时网络失败 | 只在规定次数内重试，且总超时仍生效 |
| HTTP 错误、未知结果码或结构异常 | 返回分类错误，不透传响应正文 |
| 成功响应缺少必要 Cookie | 不得报告成功或保存半有效凭据 |
| Credential Manager 保存失败 | 登录整体失败，不声称凭据可复用 |

时间、等待、HTTP 和二维码渲染均使用测试替身。测试应验证只申请一次二维码、等待间隔和调用次数符合配置、所有终止路径有限结束。

## 认证命令场景

| 命令与状态 | 期望结果 |
|---|---|
| `auth login` 且已有有效凭据 | 返回 `0`；报告已经登录，不申请二维码 |
| `auth login` 且无、损坏或失效凭据 | 启动一次二维码登录；保存成功后返回 `0` |
| `auth login` 过期、取消、超时或操作失败 | 返回 `2`；原因明确且无秘密泄漏 |
| `auth status` 且凭据有效 | 返回 `0`；显示已登录及允许的非秘密信息 |
| `auth status` 且无、损坏或失效凭据 | 返回 `1`；不申请二维码，不改写凭据 |
| `auth status` 遭遇网络、平台或存储错误 | 返回 `2`；不把不确定状态报告为未登录 |
| `auth clear` 且凭据存在或不存在 | 返回 `0`；不发起网络请求 |
| `auth clear` 删除失败 | 返回 `2`；不声称已经清除 |

CLI 测试必须锁定简体中文状态标签、标准输出/错误边界和退出码，同时确认二维码仅在需要登录时渲染。

## 主命令自动恢复场景

| 初始认证状态 | 期望结果 |
|---|---|
| 有效凭据 | 不显示二维码；使用凭据继续原元数据流程并返回原结果 |
| 没有凭据 | 完成一次扫码登录并保存；自动继续原任务，无需重新执行命令 |
| 凭据格式损坏或在线判定失效 | 不发送损坏凭据；完成一次登录后继续原任务 |
| 登录过期、取消、超时或失败 | 返回 `2`；不执行后续元数据请求，不创建输出文件 |
| 登录成功后原请求再次判定认证失效 | 返回 `2`；不得再次申请二维码或循环恢复 |
| 恢复后的元数据请求失败 | 保持阶段二错误分类与安全输出，不把它误报为登录失败 |

测试必须证明恢复前后视频输入、URL `p`、`--page`、`--all-pages`、`--lang` 和 `--force` 参数不变；自动恢复最多一次，元数据成功仍只产生阶段二摘要。

## 安全与秘密泄漏审计

- 在测试中使用唯一的伪 Cookie 值、序列化凭据、二维码密钥和二维码原始内容作为金丝雀。
- 断言标准输出、标准错误、日志、异常消息、对象 `repr`、pytest 快照和失败诊断均不包含任何金丝雀。
- 断言二维码内容与轮询密钥不进入凭据对象，Cookie 不进入领域认证状态或 CLI 渲染模型。
- 固定响应不得包含真实账号、Cookie 或可用二维码；人工验收记录只记录状态和时间，不记录二维码或账号数据。
- 搜索仓库确认没有明文凭据文件、Cookie 命令行选项、环境变量降级或调试打印。
- 测试失败时也必须满足秘密不进入断言差异或 HTTP 请求转储。

## 架构与范围检查

- 领域层只使用标准库类型，不导入 Typer、Rich、HTTPX、keyring、qrcode 或 Bilibili 适配器。
- CLI 不直接读取 keyring、不拼装认证 HTTP 请求、不持有或打印 Cookie。
- 服务名、账号槽位、平台接口路径、结果码和响应解析集中在基础设施适配层。
- 二维码密钥和二维码内容只有单次登录会话生命周期；长期凭据只包含恢复 Web 会话所需 Cookie。
- 新增直接运行时依赖仅为 `keyring`、`qrcode` 和阶段二已有依赖；依赖树不含浏览器自动化、媒体下载、FFmpeg、ASR、OCR 或绕过工具。
- 不存在字幕轨道发现、正文下载、JSON/SRT/manifest 写入或 `subtitles/` 创建路径。

## Windows 人工验收

在不会暴露屏幕内容或录制二维码的 Windows 终端中完成：

1. 备份并避免覆盖现有默认槽位；如无法隔离，应使用专用测试槽位执行存储适配器验收。
2. 执行 `uv run bili-subtitle auth clear`，确认不存在时也能明确成功。
3. 执行 `uv run bili-subtitle auth login`，扫码并确认登录；终端不得显示二维码原始文本或 Cookie。
4. 新终端执行 `uv run bili-subtitle auth status`，确认凭据可跨进程复用。
5. 对一个受支持 UGC 输入执行主命令，确认不重新显示二维码且阶段二摘要成功。
6. 清除或使测试凭据失效后再次执行主命令，确认扫码成功后自动恢复原任务一次。
7. 另行验证一次用户取消，以及可安全制造时验证二维码过期；两者都必须有限结束且无堆栈。
8. 执行 `auth clear` 并确认测试凭据已删除；验收记录不得包含账号标识、Cookie、二维码或响应正文。

## 可合并条件

- 上述自动化、凭据、状态机、认证命令、主命令恢复和安全场景全部通过。
- [`requirements.md`](./requirements.md) 的范围、契约和已确定决策均有实现或测试保护。
- 未扫码、待确认、成功、过期、取消和失败状态均被明确覆盖，登录流程具有可证明的总超时。
- 有效凭据可跨进程复用，失效时可重新登录；原命令只恢复一次且参数不变。
- Cookie、二维码密钥和二维码原始内容未出现在输出、异常、快照、文件或长期领域对象中。
- Windows Credential Manager 和真实扫码人工验收有不含秘密的记录，测试凭据已清除。
- 阶段一、阶段二回归、Ruff、格式检查、strict Pyright、覆盖率门槛和 Windows CI 全部通过。
- 锁文件、feature spec 和实现保持一致，工作区除本 feature 的预期文件外没有无关改动。
